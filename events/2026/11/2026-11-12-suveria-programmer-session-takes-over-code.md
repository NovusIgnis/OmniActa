### Suveria: a separate programmer session takes over the code and lists the conditions before a real gateway

On 12 November at 17:29 the founder decided to set up a separate session of Claude for programming Suveria. Until then one session, the coordinator, wrote the code and at the same time kept the foundation's working memory, talked with the founder and gathered results from the other sessions. From now on the coordinator commissions work and collects results, and the programmer session writes the code, the tests and the evidence that goes to review by a second model.

The handover was a file written by the coordinator: where the code is, what has been checked and by whom, which of the founder's decisions bind the programmer, and what the coordinator did not check. The code changed hands at 22:37, only after increment 14 of the home was finished and its review recorded. Until then the programmer session only read.

One boundary carries over unchanged: no agent opens the container of the trial Suveria or reads the record of the founder's conversations or service logs that contain content. Faults are diagnosed from the code and, at most, from metadata without content.

Before touching the code, the programmer session collected from the recorded reviews 4 to 13 a list of conditions to meet before the home is connected to a real gateway and a real model, before synchronisation and before import. The list gives the state of each item as the reviewer described it. The new session has not yet checked any of it in the code. Open before a real gateway at that moment: three items on the conversation page (in the scope of increment 14), agreement of policy between programs that is not enforced, older answers without sources, branches that are neither merged nor reviewed together, and the fact that the home has never run with a real gateway.

**What we do not claim:** the home is code with tests. Nobody has installed or used it. The list is a working document, not a result.

## PL

### Suveria: osobna sesja programisty przejmuje kod i spisuje warunki przed rzeczywistą bramą

12 listopada o 17:29 fundator zdecydował o założeniu osobnej sesji Claude'a do programowania Suverii. Do tej pory jedna sesja, koordynator, pisała kod i jednocześnie prowadziła pamięć roboczą fundacji, rozmawiała z fundatorem i zbierała wyniki pozostałych sesji. Od teraz koordynator zleca prace i zbiera wyniki, a sesja programisty pisze kod, testy i dowody, które idą do przeglądu drugiego modelu.

Przekazaniem był plik napisany przez koordynatora: gdzie jest kod, co zostało sprawdzone i przez kogo, które decyzje fundatora wiążą programistę i czego koordynator nie sprawdzał. Kod zmienił gospodarza o 22:37, dopiero po zakończeniu przyrostu 14 domu i zapisaniu jego przeglądu. Do tego czasu sesja programisty tylko czytała.

Jedna granica przechodzi bez zmian: żaden agent nie otwiera kontenera Suverii próbnej i nie czyta zapisu rozmów fundatora ani dzienników usług zawierających treść. Błędy diagnozuje się z kodu i najwyżej z metadanych bez treści.

Zanim dotknęła kodu, sesja programisty zebrała z zapisanych przeglądów od 4 do 13 spis warunków do spełnienia przed podłączeniem domu do rzeczywistej bramy i rzeczywistego modelu, przed synchronizacją i przed importem. Spis podaje stan każdej pozycji tak, jak opisał go recenzent. Nowa sesja niczego z niego nie sprawdziła jeszcze w kodzie. Otwarte przed rzeczywistą bramą w tamtej chwili: trzy pozycje na stronie rozmowy (w zakresie przyrostu 14), niewymuszona zgodność polityki między programami, starsze odpowiedzi bez źródeł, gałęzie niescalone i nieprzejrzane razem oraz to, że dom nigdy nie działał z rzeczywistą bramą.

**Czego nie twierdzimy:** dom to kod z testami. Nikt go nie instalował ani nie używał. Spis jest dokumentem roboczym, nie wynikiem.
